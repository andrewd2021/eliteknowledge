What this plugin is

Elite Knowledge is two products in one install: a knowledge base (Topics, FAQ, Documents) and a member forum (Forums → Discussions → threaded Replies), tied together by shared search, a role/verification permission model, and a settings screen that controls how open or gated each part is.

AreaContent typeWhat it's for
Knowledge Topicsek_topicLong-form articles/guides, browsable by category and tag.
Forumsek_forumNamed forum sections that hold Discussions (e.g. "General Discussion").
Discussionsek_discussion + WP commentsMember-started threads inside a forum; replies use core comments under the hood.
FAQek_faqAccordion or grid of question/answer pairs, with "was this helpful" voting.
Documentsek_documentVersioned file downloads with five access levels, from public to named users.

Nothing here needs another plugin — no page builder, no ACF, no custom database tables. It runs on whatever theme is active and stores everything in core WordPress tables, which matters for the removal test in Phase 7.

Phase 1

Install & activate

What just happened, invisibly

Activation added a set of ek_* capabilities to the Administrator, Editor, Author, Contributor, and Subscriber roles, seeded the ek_settings option with sane defaults, and flushed rewrite rules. None of this touches any other plugin or theme data.

Phase 2

Initial configuration

Everything here lives at Knowledge Center → Settings. Full field-by-field reference is in the Settings table — this phase just confirms each control actually does what it says.

Theme content mode

Turning on "Use the theme's own page template" routes single/archive views through the active theme's normal single.php/page.php via the_content, instead of the plugin's own full-page templates — useful when a theme's header/sidebar must always appear, but it also disables the built-in archives, so every section then depends on the landing pages above existing. Worth a dedicated pass with it toggled on if the site's theme needs that.

Phase 3

Load demo content

Knowledge Center → Demo Data gives you one click to populate every module with realistic sample content, which makes Phase 4 far faster to run.

Phase 5

Guest, signup & verification flow

This is the journey every new member actually takes, end to end — worth running exactly in this order once, since it's the flow most support questions will be about.

Why this matters for support

"I registered and can't post" is the single most likely ticket this plugin generates. The fix is always the same: Users → find them → Verify.

Phase 6

Roles & permissions

Two separate systems stack on top of each other, and it's worth testing both independently so a support request ("why can't X post?") is quick to diagnose.

  1. Role whitelist (Settings → "Who can start discussions" / "Who can reply") — a straight checklist of which roles are allowed at all, including any custom roles your site defines.
  2. Verification (Phase 5) — a per-account manual flag on top of the whitelist. Even a whitelisted role can't post until verified.

Phase 7

Removal & uninstall

Save this for last — it's destructive by design. Confirm behavior in both directions: a safe deactivate, and an intentional full wipe.

Deactivate only

Full uninstall

Before you do this on a real site

Without that checkbox ticked, deleting the plugin leaves every discussion, document, and setting sitting inertly in the database indefinitely — which is usually what you want. Only tick it when the intent is a genuine, permanent wipe.

Troubleshooting

Titles or headings look oversized, cut off, or misaligned

Themes sometimes ship their own global heading styles (a big fluid h3 font size, for instance) that can collide with the plugin's card layouts. This plugin also supports themes shipping their own template overrides in a elite-knowledge/ folder inside the theme — if a theme has one, check its stylesheet for generic heading rules first; that's the more likely culprit than the plugin's own CSS.

A brand-new member says they can't post anything

Check, in order: are they logged in at all → is their role checked under Settings → "Who can start discussions/reply" → have they been Verified on the Users list (Phase 5). The three failure states show visibly different notices on the front end, which tells you which one you're looking at without needing to check the database.

A document's file downloads even though it should be restricted

Confirm the file was actually uploaded through the document's own "Select File" button in wp-admin, not attached directly through the normal Media Library — only files added that way get moved into the access-controlled storage location and have their direct URLs blocked.
